# Tasks Calendar 验收

日期采用浏览器本地全天日期。`actual_completion_date` 为真实完成日；`completed_at` 保留完成操作的 UTC 时间。已有记录在新日期为空时按本地时区解释 `completed_at`，不会在迁移时猜测历史时区。

## 手动场景

以本地今天为参照创建任务，避免使用未来的实际完成日期。

| 场景 | 预期 |
| --- | --- |
| 开始为今天前 8 天，截止前 4 天，完成前 1 天 | 正常段与橙色段连续，延期 3 天，截止与完成节点分别可见 |
| 同样计划，尚未完成 | 橙色段延伸至今天，显示仍未完成；跨午夜或重新聚焦页面后更新 |
| 截止前 2 天已完成 | 完成后至截止日为淡色计划尾段，点击尾段日期不列入当日任务 |
| 截止日当天完成 | 无橙色段，截止和完成节点在同一天 |
| 跨周、跨月并与多个任务重叠 | 同一任务保持泳道、每周重复标题，各段无覆盖；切月后完整显示可见部分 |
| 无开始日、无截止日、仅有开始日、完全无日期 | 使用约定回退起点；无截止日不计算延期；仅开始日显示单日；无日期可从全部任务进入 |
| 勾选完成、补填旧日期、重新打开 | 默认本地今天；修正不改变操作时间；重新打开清除两种完成信息 |
| 无效日期、完成日早于开始日/晚于今天、截止早于开始 | 表单或 API 明确拒绝，输入不丢失 |
| 断网时保存、完成、删除 | 保存失败保留弹窗内容；完成和删除回滚并 Toast 提示；删除确认仍保留 |
| 键盘与窄屏 | 任务条/日期/标题可聚焦；编辑弹窗 Tab 循环、Escape 关闭并恢复焦点；Calendar 可横向滚动 |
| 深浅主题与历史记录 | 四种颜色和节点可辨认；历史记录日期按浏览器本地展示；更换浏览器时区不改变明确填写的全天日期 |

## 自动化用例（未自动执行）

- 后端：`cd backend && uv run python -m unittest tests.test_task_completion_dates`。
- 日期逻辑：在支持 TypeScript stripping 的 Node 版本中，`cd frontend && node --experimental-strip-types --test tests/taskTimeline.test.ts`。
- 涉及新数据库或热切换数据库时，由现有 Alembic 流程升级到 `d2e3f4a5b6c7`，schema 检查须包含 `user_task.actual_completion_date`。

本次实现不直接修改用户数据库；部署时需先完成 migration，再提供新版 API。
